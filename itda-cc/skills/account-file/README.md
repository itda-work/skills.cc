# account-file

itda-cc 스킬(email·calendar·dart·ecos)이 읽는 계정 파일 `계정.toml` 을 **만들고, 열고, 검사하고, 고치고, `.env` 에서 옮기는**
Claude Code 전용 스킬.

이 README 는 개요와 **할 수 없는 일**의 목록이다. 사용 절차는 **[GUIDE.md](GUIDE.md)**, 실행 계약은 **[SKILL.md](SKILL.md)**,
변경 이력은 **[CHANGELOG.md](CHANGELOG.md)** 를 본다.

---

## 기능

| 명령 | 하는 일 | 파일에 쓰는가 |
|---|---|---|
| `create` | 예시 묶음이 든 틀을 만든다. `--provider`·`--email`(·`--sender-name`)을 주면 그 메일 묶음의 `메일`·`보내는이름` 을 채운다 | 새 파일만(이미 있으면 쓰지 않음) |
| `open` | 편집기로 연다(Windows 메모장 · macOS 텍스트 편집기) | 아니오 |
| `check` | 문법·일부만 채운 묶음·두 파일 동시·권한을 보고, 쓸 수 있는 계정을 알린다 | 아니오 |
| `fix` | 답이 하나뿐인 실수만 고친다(따옴표·묶음 이름 꼴·값 앞뒤 빈칸·`\`) | 예 — 고치기 전 사본을 옆에 남긴다 |
| `migrate` | `.env` 를 `계정.toml` 로 옮긴다(꼬리말 → 별칭 묶음) | 새 `계정.toml` |

**값 비노출** — 결과에는 줄 번호·묶음 이름·칸 이름만 싣는다. 비밀번호·키는 물론 메일 주소도 되읽어 주지 않는다.

## 쓸 수 있는 묶음과 칸 (고정)

| 종류 | 묶음(제공자) | 칸 |
|---|---|---|
| 메일 | `naver`·`gmail`(`google`)·`daum`·`icloud` — 별칭은 점 뒤(`gmail.회사`) | `메일`·`앱비밀번호`, 선택 `보내는이름` |
| 키 | `dart`·`ecos` | `키` |

칸 이름은 영문(`email`·`app_password`·`key`·`sender_name` 등)도 받는다. 정본: `itda-cc/shared/cc_account_toml.py` 의
`PROVIDERS`·`FIELD_NAMES`.

## 한계 — 지금 할 수 없는 일

### 커스텀 값

- **목록 밖의 칸·묶음은 쓰이지 않는다.** 모르는 칸은 `unknown_field`, 모르는 묶음은 `unknown_provider` 경고를 내고 넘어간다.
  오류는 아니어서 파일은 계속 읽히지만, 그 값을 받아 쓰는 스킬이 없다.
- **커스텀 값을 넣기·지우기·읽기 명령이 없다**(`set`·`unset`·`get` 류 없음). 새 API 키를 담을 자리도 없다 — 새 키를 쓰려면
  `PROVIDERS` 에 묶음을 더하고 그 키를 쓰는 스크립트를 함께 만들어야 한다(dart·ecos 가 그렇게 되어 있다).
- **환경변수로 올려 주지 않는다.** itda-cc 는 프로세스 환경변수를 읽지도 쓰지도 않는다(키는 계정 파일 하나에서만 읽는다).
  계정 파일 값을 자식 프로세스의 환경변수로 넣어 주는 기능도 없다 — 실행할 명령을 Claude 가 고르는 한, 그 명령이 값을
  출력할 수 있어 비노출을 보장하지 못하기 때문이다.

### 쓰기

- **이미 있는 파일에는 값을 넣지 않는다.** 메일 칸 채우기는 `create` 가 새 파일을 만들 때만 한다. 이미 계정 파일이 있으면
  `open` 으로 열어 사용자가 직접 적는다(예외는 `fix` 의 형식 교정뿐이다).
- **앱비밀번호·키는 스크립트가 채우지 않는다.** `--password` 류 옵션은 `secret_field_refused` 로 거부하고, 대화로 받은 값도 쓰지 않는다.
  `--provider` 는 메일 묶음만 받는다 — `dart`·`ecos` 의 `키` 는 사용자가 연 파일에 직접 적는다.
- **파일을 지우지 않는다.** 한 폴더에 `.env` 와 `계정.toml` 이 함께 있으면(`account_file_conflict`) 어느 쪽을 남길지 사용자가 정한다.
  `fix` 가 남긴 `계정.toml.고치기전-<시각>.bak` 도 사용자가 지운다(그 사본에도 비밀번호가 있다).

### 검사·고치기

- **값을 보여 주지 않으므로 "값이 맞는지" 는 알 수 없다.** `check` 는 형식(따옴표·`@` 유무·빈 칸)만 본다. 비밀번호가 틀렸는지는
  email·calendar 가 실제로 접속할 때 드러난다.
- **답이 둘 이상인 실수는 고치지 않는다.** 같은 칸 두 번·모르는 제공자·`@` 없는 주소·일부만 채운 묶음은 줄 번호만 알린다.

### 형식·환경

- **회사 메일(`SMTP_*` 등)·회사 CalDAV(`CALDAV_*`) 는 칸이 없다.** `migrate` 는 네이버·Gmail·다음·아이클라우드 메일과 DART·ECOS 키만
  옮기고, 그 밖의 키가 든 `.env` 는 `unsupported_keys` 로 멈춘다 — `.env` 를 계속 쓴다.
- **계정 파일은 하나만 읽는다.** `--env-file` > 현재 폴더 > 홈 순으로 처음 찾은 파일 하나이고, 여러 파일을 합치지 않는다.
- **표준 TOML 도구로는 열리지 않을 수 있다.** 한글 칸 이름에 따옴표를 붙이지 않아도 되는 itda-cc 전용 꼴이다.
- **`계정.toml` 판독·채우기는 Python 3.11 이상**이 필요하다(`.env` 는 3.10 도 된다).
